# Security review (design): Operator Toolkit (slug: operator-toolkit)

**Verdict headline.** F4 is buildable, but **the PRD's §5.5.5 projection is provably insufficient as written.** `response_headers` are published verbatim (AC-44a) while AC-34 forbids `token` and `matched_rule_id` — and **every** persisted response-header map contains `x-hookbox-endpoint: <token>` and `x-hookbox-rule-id: <id>` (`backend/src/interceptor/engine.rs:584-588`, captured verbatim at `:636-644`). Two ACs in the same document contradict each other; an engineer could resolve that by weakening AC-34. Separately, **F7 + `default_mode="echo"` silently defeats the existing request-header redaction**: the echo payload serialises the *raw* header map (`engine.rs:514-523`) while redaction is applied only to the `request_headers` column (`:674`), so from F7 onward the caller's `Authorization`/`Cookie` is persisted in `response_body`, CSV-exported by F5, and shown to unauthenticated share viewers by F4.

## 1. Threat model

**Assets (ranked).** A1 `owner_secret` — `localStorage['hookbox-owner-secret']` (`src/api/session.ts:17-19`), sha256 at rest (`backend/src/auth.rs:42-48`). A2 captured traffic — `request_logs`, 100 rows/endpoint, 24 h TTL (`backend/src/config.rs:156-157`), now including response bodies. A3 **endpoint token** — also present in every trace row's `response_headers['x-hookbox-endpoint']`. A4 **share code** — a new bearer credential carried in a URL path. A5 upstream secrets in response headers/bodies (`Set-Cookie` from MITM/tunnel). A6 endpoint config (`target_url` etc., mutable via `PATCH` at `backend/src/routes/api.rs:380-481`).

**Trust boundaries.** The three planes are unchanged (`backend/src/planes.rs:131-180`). F4 adds one boundary — `GET /api/share/{code}/requests[/{id}]` and the `/s/{code}` document, reachable by anyone, no credential — and F7 widens an existing one: a webhook caller can now cause the *response* to be persisted too.

Three existing properties that shape everything below:
1. **No cookies anywhere.** Header-only capability, `credentials:'omit'` (`src/api/client.ts:82-86`, `src/api/session.ts:8-12`). That is why HookBox needs no CSRF tokens, and why a share 401/404 cannot log an owner out (`noAuth` skips `session.clear()`, `src/api/client.ts:99-105`).
2. **The viewer page is same-origin with the dashboard**, where A1 lives in `localStorage`. XSS on a page made entirely of attacker-supplied text = owner takeover. There is **no CSP, no `Referrer-Policy`, no `X-Frame-Options`** anywhere today (zero `add_header`/`Content-Security` hits across `deploy/`, `index.html`, `backend/src/`).
3. **Redaction today is a HookBox-capability scrubber, not a secret scrubber.** `REDACT_HEADERS = ["authorization","cookie","x-owner-id"]` (`backend/src/helpers.rs:32-34`) exists to keep HookBox's own cap out of traces. Reading it as "secrets are redacted" is the mistake R11 and S-3 both trip over.

**S-1 detail.** `identified()` stamps `x-hookbox-endpoint` on every mock response (`engine.rs:584`), and `spawn_trace` always receives the *identified* response (`:84-98`, `:275-293`, `:330-348`, `:360-386`). With the token an unauthenticated viewer can: `POST {PUBLIC_BASE_URL}/e/<token>` to **write** into the owner's endpoint; flood ≥100 requests to evict the very evidence being shared (write-time prune at `db.rs:91-103`); mutate CRUD collections when `auto_crud` is on (`engine.rs:404-429`); make HookBox forward attacker-chosen requests to the operator's `target_url`, one upstream call per hit (`engine.rs:462-511`, SSRF guard only blocks private ranges and only when `MITM_ALLOW_PRIVATE=false`, `ssrf.rs:65-96`); and with echo mode, send a request and read it back through the link — a full read/write channel. "Read-only share link" is falsified.

**S-3 detail.** After F7 the same row reads `request_headers: {"authorization":"<redacted>"}` and `response_body: {"headers":{"authorization":"Bearer eyJ…"}}`. Fix on the persist path only (`redact(&headers_lower)` for the persisted copy) so client bytes stay byte-identical and AC-72 / the §2 non-goal both hold.

**S-4 — the R11 ruling you asked for, explicit.** `redact()` is not applied to the response map (`engine.rs:636-644`) and MITM copies upstream headers wholesale (`:482-484`). My call: **keep verbatim for the owner Inspector and the F5 CSV (ACCEPTED)** — the operator is proxying to a backend they own, "why didn't my cookie stick?" is the whole point of an inspector, and the CSV is a file they asked for; redacting on the persist path would also silently change existing rows' meaning. **Override for F4 (MUST)** — the audience becomes "anyone with a URL", and an upstream `Set-Cookie` handed to a stranger is a session-hijack primitive **on a third-party system** with HookBox as the delivery mechanism. So the required change is **one deny-list at the public projection**, which fixes S-1, S-2 and S-4 together, changes no §5 shape, and is narrower than R11's own suggested alternative. Residual, accepted: the DB holds upstream cookies for ≤ 24 h (`config.rs:157`).

**S-5 detail — §5.9.3's mechanism is necessary but not sufficient.** Landing on `/s/<CODE>` returns `index.html` (log suppressed), then the browser fetches `/assets/index-*.js`, CSS, fonts under `location / { try_files … }` (`deploy/nginx.conf:9-11`) which has no `access_log off`; those carry `Referer: https://host/s/<CODE>` (same-origin requests send the full path) and nginx's default `combined` format logs `$http_referer`. Same leak class as `47a267c`, different location. Fix: `Referrer-Policy: no-referrer` on the viewer document **in addition to** `access_log off`.

**S-6 detail.** Until now limiter keys were `rl:<token>` — cardinality bounded by owner-created endpoints. A per-IP key on an unauthenticated route makes the key space attacker-controlled: at `MAX_BUCKETS = 100_000` (`limiter.rs:43`) every request runs `evict_one_idle()`, a full O(n) DashMap iteration (`:88-90`, `:130-142`); eviction is namespace-blind, so filling the map **flushes mock-plane rate-limit buckets**, letting anyone exceed an endpoint's configured `rate_limit_per_min`; and the limiter fails open (`:7-8`, `:80-83`). Egress is also unbounded by request count alone — a detail response can carry 2 × `MAX_BODY_BYTES` ≈ 512 KB.

**S-11 detail.** "Validate fully before any write" is sufficient for *integrity* but says nothing about *intent*. A mailed bundle can silently re-point `target_url` (validated only for scheme+host, `helpers.rs:130-148`) so every future webhook is copied off-box; flip `default_mode`/`cors_enabled`/`auto_crud`; and add a catch-all rule (AC-18 never deletes, so the operator sees no loss). Verified good news: **no SSTI** — closed-grammar scanner, `{{7*7}}`/`{{config}}` are unknown tags returned verbatim (`templating.rs:1-12`, `:158-185`); and **`webhook_action` is inert** — parsed, stored, compiled (`models.rs:192-196`, `rule_cache.rs:100-116`, `matcher.rs:134`) but there is **no dispatch site anywhere in `backend/src`**, so an imported `webhook_action.url` cannot SSRF today.

**Already fine, with evidence (so nobody re-litigates):** CSRF is closed by design for F1/F3/F4/F5/F6 (header-only cap + `credentials:'omit'`, no CORS layer on P2) — AC-2's confirm is about accidents and is proportionate given 100-row/24 h ephemerality plus the Settings precedent (`src/screens/settings.tsx:445-455`); F6 needs no matcher change (AC-63 correct: `matcher.rs:182`, `:53`); F5's formula guard and RFC-4180 quoting are right; all SQL in the touched code is parameterised, including the dynamic PATCH builders (`routes/api.rs:485-502`).

## 3. Required security ACs (fold into §4 at REVISE)

**F4** — **AC-S1 (MUST)** public response-header deny-list in `share.rs`: drop `x-hookbox-endpoint|rule-id|served-by|plane|truncated`; value→`<redacted>` for `set-cookie`, `set-cookie2`, `authorization`, `proxy-authenticate`, `www-authenticate`; test that a MITM `Set-Cookie: sid=abc` shows `<redacted>` publicly **while** `GET /api/requests/{id}` still shows `sid=abc`. **AC-S2 (MUST)** token-absence asserted *after* the filter, for all eight `served_by` paths, scoped to server-generated fields (caller-supplied `path`/`query_params`/`request_body` are in the projection by design, so an unscoped substring test is flaky and will get weakened). **AC-S3 (MUST)** echo `response_body` persisted from `redact(&headers_lower)`; client body still contains the secret, stored/CSV/public all show `<redacted>`. **AC-S4 (MUST)** row-level invariant: nothing masked in `request_headers` appears verbatim elsewhere in the row. **AC-S5 (MUST)** `/s/{code}` carries `Referrer-Policy: no-referrer` + `X-Robots-Tag: noindex, nofollow`; Playwright asserts no request from the page carries a `Referer` containing the code. **AC-S6 (MUST)** `access_log off` on `location /api/share/` and `/s/` plus an assertion the app's `tracing` never emits the code (no `TraceLayer` exists today — `router.rs:178-193`; keep it that way here). **AC-S7 (MUST)** namespaced, separately-bounded limiter keys that cannot evict `rl:<token>`; check runs **before any DB read**; test 100k IPs then assert endpoint limits still enforced, latency stable, buckets bounded; do not copy `routes/api.rs:304-326`. **AC-S8 (MUST)** viewer stops polling on 404, backs off on 429 per `Retry-After`. **AC-S9 (MUST)** resolver requires `revoked_at IS NULL` **and** `endpoints.gone_at IS NULL`; tombstone revokes shares *before* writing `gone_at` (or one transaction); test with the revoke forced to fail. **AC-S10 (MUST)** `last_used_at` off-path and ≤1 write/code/60s, or dropped. **AC-S11 (MUST)** mint-time disclosure naming bodies **and** response bodies **and** both header maps, up to the last 100 requests, **including other people's requests** and pre-mint ones. **AC-S12 (SHOULD)** scope to `created_at >= share.created_at`. **AC-S13 (MUST)** no user value into `href`/`src`/`srcdoc`/`style`/`on*` (extends AC-67, which only covers innerHTML); viewer module graph must not import `src/api/session.ts`. **AC-S14 (MUST)** 404 identity across status line, body **and headers**, including `HEAD` (axum auto-implements it; rate-limit it too). **AC-S15 (SHOULD)** global resolver ceiling + documented 512 KB worst-case detail egress. **AC-S16 (MUST)** codes never in an error `detail`, log line, public body, or the F3 bundle.

**F7** — **AC-S17 (MUST)** truncation at row-build precedes all three surfaces (assert stored length), and the mid-multibyte case must still return a normal 2xx **and** still write a trace — today the panic is on the request task (`rec` built before `tokio::spawn`) with no panic layer, so the current failure mode is a dropped connection, not just a lost body. **AC-S18 (SHOULD)** add `CatchPanicLayer`. **AC-S19 (MUST)** truncate MITM/tunnel bytes to `MAX_BODY_BYTES` *before* moving them into the spawned task (`MITM_MAX_BODY_BYTES` is 5 MB, `config.rs:177`). **AC-S20 (MUST)** no new awaited I/O on the mock path; note for QA that `insert_trace` is **two** statements (`db.rs:66-103`), so AC-73(b)'s baseline is "unchanged", not "one".

**F3** — **AC-S21 (MUST)** pre-apply diff + explicit confirm; every changing config field old→new with `target_url` called out as traffic-affecting; zero requests until confirm. **AC-S22 (MUST)** `.strict()` at **every** level (assert a nested unknown key is rejected); import calls only PATCH-endpoint + POST-rules; bundle can carry no token/owner/share/trace data. **AC-S23 (SHOULD)** warn when a rule uses `{{request.header.*}}`.

**Cross-cutting** — **AC-S24 (MUST)** CSRF regression assertion (no `Authorization` ⇒ 401, nothing deleted; no cookies sent) and a §4 statement that no CSRF token is needed. **AC-S25 (MUST)** F5's CSV assertions updated to expect the S-3 outcome (`<redacted>` in echo `response_body`); `response_headers` cells stay verbatim per the S-4 ruling. **AC-S26 (SHOULD)** baseline headers: `Referrer-Policy`, `X-Content-Type-Options`, `X-Frame-Options`/`frame-ancestors`, starter CSP (note the inline theme script at `index.html:11-33` needs a nonce/hash). **AC-S27 (SHOULD)** `robots.txt` `Disallow: /s/`.

## 4. §5 contract notes

(1) `PublicRequestDetail.response_headers` is a **filtered** map — freeze both lists as named constants; the AC-34 omission list governs *projection keys*, the filter governs *keys inside `response_headers`*. (2) Reconcile AC-34 vs AC-44a in the frozen text: `response_headers` stays *because* AC-S1 makes AC-34 true. (3) Freeze a redaction table: request headers redacted / response headers verbatim-at-rest but filtered publicly / bodies verbatim **except** the echo payload's `headers` sub-object. (4) `Cache-Control: no-store` (AC-37) plus the two viewer-document headers. (5) Rate limiting is contract, not implementation: pre-DB, namespaced, bounded, `HEAD` counted, `Retry-After` (`error.rs:66-69`), and write down the topology assumption (`routes/api.rs:273-299`) with the compose caveat. (6) Share `url` from `PUBLIC_BASE_URL` or origin-relative, **never** from `Host`/`X-Forwarded-Host` — host-header injection would make the owner hand the code to an attacker's domain. (7) Liveness predicate `revoked_at IS NULL AND gone_at IS NULL`, read per request, never from `rule_cache`; shape check `^[A-Za-z0-9_-]{32,64}$` → 404 before any DB read. (8) Respecify or drop `last_used_at`. (9) **`SHARE_CODE_BYTES=24` (192 bits) is confirmed correct** — 128 would suffice given the limiter; 192 costs nothing, reuses `ids.rs:41-45`; **add a floor of 16 in `Config`**, because `int_env` will happily accept `SHARE_CODE_BYTES=1` today (`config.rs:17-22`). (10) **Plaintext storage APPROVED (R3 resolved), conditionally** — at 192 bits there is no offline guessing, so hashing only helps in the DB-disclosure case where the attacker already holds every trace the link would reveal; the one real delta (a stolen code outliving DB access) is outweighed by re-copy + unambiguous revoke UX. Conditions: codes never logged (AC-S5/S6), never in an error detail or the F3 bundle (AC-S16), revocation immediate (AC-37/AC-S9), and **revisit if a DB backup/export or admin dump ever ships** — there is none today (the 18 routes at `routes/api.rs:981-1012` contain no backup/export surface). Keep `ShareLinkCreated = ShareLink`, no "shown once". (11) State `share_links` retention: revoked rows never re-minted; tombstoned endpoints' rows vanish via `ON DELETE CASCADE` when the sweep hard-deletes at `GONE_TTL_HOURS` (`sweep.rs:61-69`), which works only because `foreign_keys` is on (`db.rs:21`). (12) `PublicShareFeed.endpoint.name` is operator-authored text rendered to strangers — intentionally disclosed, text node only. (13) No SSR/OG tags on `/s/{code}` so a link unfurler cannot render data into a chat preview.

> **Note on the architecture.md decision this reviews:** system-architect independently resolved the plaintext-vs-hashed share-code storage question to **hashed** (`code_hash = sha256(code)` + a non-secret integer `id` for revoke) to avoid a live bearer credential landing in the owner-side nginx access log via `DELETE /api/endpoints/{token}/shares/{code}`. This security review's item (10) above was written analyzing plaintext storage on its own merits and reached a conditional approval for plaintext; it does **not** account for architecture's separate D10 finding (the owner-revoke-route log-leak problem), which independently mandates revoking by non-secret `id` rather than by the raw code regardless of at-rest storage. **PM: treat architecture's hashed+id design as authoritative for REVISE** — it satisfies this review's four plaintext conditions from an even stronger position (the code is never in the DB at all, only its hash) and additionally closes the owner-side log-leak gap that this review did not evaluate. Do not re-open R3 in favor of plaintext.

## 5. Open security questions

**OQ-S1** — adopt AC-S12 (scope the window to mint time)? The only finding where security costs product behaviour. Recommendation: **adopt**; add an "include earlier requests" toggle later if asked. If declined, AC-S11's pre-mint clause becomes mandatory. **OQ-S2** — `Referrer-Policy` via `<meta>` in `index.html` (covers every deployment) or nginx `add_header` (right layer, nginx-only)? Recommendation: both, meta first. **OQ-S3** — is 60/min the right default given 12 req/min per polling viewer plus S-6b's IP collapse? I would start at 120/min per IP with a global ceiling. **OQ-S4** — should the CSV carry a redaction note (a comment line is impossible in frozen RFC-4180)? PM's call.
